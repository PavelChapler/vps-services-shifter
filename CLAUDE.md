# Phantom Lendings — Project Instructions

## Продукт
**Phantom Lendings** — фабрика рекламных лендингов (одностраничников) под разные домены, гонящих трафик на VPN-продукт **Xor** (бот `@VPN_XOR_FAST_bot`).

**Брендинг — фантик на домен.** Каждый домен = свой нейтральный «бренд-фантик» (НЕ «Xor»), единый шаблон. Само имя **Xor — постоянный бэкенд**: живёт в боте/бэкенде, на витрине лендинга не светится. Так домены не связываются между собой — бан рекламного кабинета или блок одного домена не палит остальные. Домены живут недолго (блокировки, ротация), поэтому принцип: **один шаблон → N доменов через конфиг**, новый лендинг поднимается за минуты.

## Две главные цели (всё подчинено им)

### 🥇 Цель 1. ТОП-1 в поиске
Лендинг должен выходить на первое место по целевым ключам (Яндекс + Google). Скорость, семантика, schema.org, низкий процент отказов — не «галочки», а условие выживания трафика. См. `.claude/agents/seo-optimizer.md`.

### ⚖️ Цель 2. Юридическая чистота по РФ
С 01.09.2025 действует **№281-ФЗ**: запрещены **реклама и популяризация средств обхода блокировок**. Штрафы: физлица 50–80к₽, должностные 80–150к₽, **юрлица 200–500к₽**, повтор — до 1 млн. Сама технология для законных целей (защита данных, удалёнка, безопасное соединение) НЕ запрещена.

**Стратегия — как у выживших конкурентов (vanya.im/vanyavps.com, bebra.lol):** позиционировать продукт как **аренду виртуального сервера / VPS / личный сервер / сервис защиты трафика**, через **законные сценарии использования**. Любой текст проходит через `.claude/agents/legal-compliance-rf.md` ПЕРЕД публикацией. Это блокирующий гейт.

## SEO-требования (база на каждом лендинге)
- Уникальные `<title>` (≤60 симв.) и `meta description` (≤155 симв.) с целевым ключом
- Один `<h1>`, логичная иерархия `h2/h3`, семантическая разметка
- Schema.org JSON-LD: `Organization`, `Product`/`Service`, `FAQPage`, `BreadcrumbList`
- Open Graph + Twitter Card, фавикон, canonical
- `sitemap.xml` + `robots.txt` на каждый домен
- Core Web Vitals в зелёной зоне (LCP < 2.5s, INP < 200ms, CLS < 0.1) — см. perf-auditor
- Без переоптимизации (переспам ключей → пессимизация). Текст для людей.
- Яндекс-специфика: поведенческие факторы решают → низкий отказ, время на странице, дочитываемость

## Копирайтинг (лестница прогрева)
Тексты строятся по воронке и «лестнице узнаваемости Бена Ханта» (см. `transcription_readable.md`, гл. 3 — основной справочник по маркетингу): от «нет проблемы» до «готов купить». Hero → выгоды → доверие (отзывы/гарантии) → FAQ (закрытие возражений) → CTA. Этичный FOMO (ограничение по времени/количеству) допустим, обман — нет (раздувает отказы и убивает SEO). Один экран — одна задача: довести до целевого действия.

## 💳 Оплата и выдача ключа (на сайте)
Оплата и выдача ключа — **прямо на лендинге** (как у bebra: `/buy/<план>?ymid=&gcid=&fcid=`). Поток: тариф → `/buy/<slug>` (e-mail + способ оплаты) → оплата у провайдера → возврат на `/success` → **ключ показывается на странице** и дублируется на e-mail.

**Метки атрибуции.** С рекламы в URL приходят `ymid` (Яндекс), `gcid` (Google), `fcid` (Facebook/Meta) + `utm_*`. Захватываются на лендинге (`Base.astro`), прокидываются в ссылки `/buy` и дальше в `success_url` провайдера — чтобы покупка засчиталась как конверсия в нужной системе аналитики.

**Провайдер: Platega** ([docs.platega.io](https://docs.platega.io)) — PSP: карты Мир/СБП/крипта. Шлюз **без авто-выдачи товара** — поэтому ключ выдаёт **наш бэкенд** по webhook'у (`issueKey()`), не провайдер. Auth — заголовки `X-MerchantId`/`X-Secret`.

**Бэкенд — тонкий общий API над Platega** (один на все домены; статичные домены дёргают через `fetch`, CORS открыт; креды Platega только server-side). Контракт:
- `POST {apiBase}/pay` `{plan,email,method,attr}` → `{url}` — создаёт транзакцию Platega (`transaction/process`, сумма из `api/products.json[plan]`), `returnUrl=…/success/?order=<id>`, возвращает ссылку на оплату.
- `POST {apiBase}/webhook/platega` — Platega шлёт статус `CONFIRMED` → бэкенд выдаёт ключ (`issueKey`) и сохраняет под order.
- `GET {apiBase}/key?order=<id>` → `{key}` — ключ после оплаты для `/success` (фронт поллит).

Фронт реализован: `/buy/[plan].astro` (создание платежа) и `/success.astro` (поллинг ключа), оба с демо-фолбэком при пустом `apiBase`. **API-сервис написан в `api/`** (Node + Express + `node:sqlite`): `/pay`, `/key`, `/webhook/platega`, пул ключей + TODO под реальный минт Xor; демо-режим без кредов (`cd api && npm run smoke`).

**Страницы оплаты** `/buy/<slug>` и `/success` — `noindex`. Тарифы/цены/оферта на сайте совпадают с реальными.

**Юр-обвязка (проверяет `legal-compliance-rf`):** оферта/реквизиты доступны; согласие на ПДн (чекбокс) у формы с e-mail; чек по **54-ФЗ** на каждый платёж; условия возврата.

> Граница: помогаю с легальной интеграцией провайдеров и on-site выдачей ключа. НЕ помогаю врать KYC-процессингу про категорию товара, с отмыванием или обходом санкций.

## Технический стек
- **Astro** — статика на выходе (идеально для SEO/скорости), компоненты переиспользуются между доменами
- **Мульти-домен через конфиг**: один шаблон, данные домена в `sites/<domain>.json` (бренд, оффер, ключевики, цены, контакты)
- Минимум JS (только то, что нужно для конверсии/аналитики) → быстрый LCP, низкий отказ
- CSS — без тяжёлых фреймворков; критический CSS инлайном
- Аналитика (Яндекс.Метрика / GA / цели) — подключается через конфиг домена, грузится отложенно

## Структура проекта (целевая)
```
phantom-lendings/
  src/
    layouts/Base.astro        — каркас: <head>, SEO-мета, schema.org, OG
    components/               — Hero, Features, Pricing, Faq, Footer, LegalLinks…
    pages/index.astro         — сборка лендинга из компонентов по конфигу
    pages/buy/[plan].astro    — on-site оформление тарифа (slug из конфига), noindex
    pages/success.astro       — выдача ключа после оплаты, noindex
    pages/legal/              — оферта, политика конфиденциальности, реквизиты
    styles/                   — токены, критический CSS
  sites/
    <domain>.json             — конфиг: фантик-бренд, оффер, ключевики, тарифы (со slug), checkout (провайдер/apiBase), аналитика, реквизиты
  public/                     — фавиконы, og-картинки, robots.txt
  astro.config.mjs
  package.json
  api/                        — общий backend над Lava.top (Node+Express+SQLite): /pay, /key, webhook
  .claude/                    — инфраструктура Claude (этот каталог)
  transcription_readable.md   — справочник по интернет-маркетингу (референс копирайтинга)
```

## Сборка / деплой
```bash
npm install
npm run dev                                  # локальная разработка
npx astro build --site https://<domain>      # билд под конкретный домен → dist/
npx astro preview                            # предпросмотр прод-сборки
```
Деплой статики на любой хостинг/CDN. Каждый домен билдится со своим `--site` и конфигом.

## Анти-блокировка доменов (устойчивость, не обман)
Домены блокируются → нужна быстрая ротация: новый домен = новый `sites/<domain>.json` + билд + деплой. Шаблон от домена не зависит. Никаких хардкодов домена в компонентах — только из конфига.

## Агенты и команды
- `seo-optimizer` — техническое + on-page SEO, ранжирование, schema, CWV-влияние
- `legal-compliance-rf` — **гейт** по №281-ФЗ, проверка любого текста перед публикацией
- `conversion-copywriter` — копирайтинг по лестнице прогрева
- `astro-landing-builder` — вёрстка/компоненты Astro, мульти-домен конфиг
- `web-perf-auditor` — Core Web Vitals, Lighthouse, вес страницы

Команды: `/new-landing`, `/copy`, `/legal-check`, `/seo-audit`, `/perf-check`.
